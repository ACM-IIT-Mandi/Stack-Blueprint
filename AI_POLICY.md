# Using AI here

Short version: AI is allowed. Submitting code you cannot explain is not.

Most of us use these tools already, pretending otherwise would be silly. But this project
exists so people understand how a well built project is put together, and code that shows up
without anyone understanding it does not help anyone, including the person who submitted it.

## Fine

- Asking it to explain a framework feature, an error message, or something you are stuck on
- Asking it to review your code or find a bug
- Getting a first draft, then reading it properly and making it your own
- Boilerplate, docstrings, formatting, checking your English

## Not fine

- Submitting code you have not read
- Generating a whole blueprint in one go and opening a pull request without running it
  yourself, this is usually where confident looking mistakes hide
- Opening several blueprint pull requests at once without having really worked on any of
  them

## What we ask

The pull request template has a short box asking you to explain, in your own words, what
your change does and one decision you made. Write that part yourself. It is usually the
moment you notice something you have not fully understood, which is a good thing to catch
early.

A reviewer may ask you about any part of your change. A plain answer is all that is needed.
"I am not sure, let me go check" is a perfectly good answer, and your pull request just stays
open while you do.

You do not need to say whether you used AI. We will only ever ask about the code itself.

## Why we care

You will graduate. The tool will still be there. The time you have right now to sit with
something until it actually clicks is the part that runs out.

Use the tool. Do not skip the understanding.
